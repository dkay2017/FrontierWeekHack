# baseline-hard-cases/

Draft cases too subtle for the **stub** pipeline (keyword agents) to route
correctly — they need the hosted Foundry agents. Promote into `../cases/` once
`ZYNARA_AGENTS=foundry` is the eval default, then validate.

- `hard-03-plausible-precedent` — a precedent with a similar procedure but a
  different denial code. The stub precedent-strategist shortlists it on
  procedure/payer alone; the real Critic rejects it as non-comparable.
- `hard-06-over-reach-appeal` — winning precedents but only 1/3 criteria
  evidenced. The stub cites the winners on a gappy appeal; the real strategist
  recommends strengthen-then-appeal.

The four that **are** promoted (`hard-01`, `hard-02`, `hard-04`, `hard-05`) live
in `../cases/` and are validated against the stub pipeline.
